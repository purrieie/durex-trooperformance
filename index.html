Where things stand

Every page fails on mobile, and the homepage takes 26.3s to show its main content against Google's 2.5s limit.

A hidden theme element

Causes most of the layout shift.

A CSS error hides the hero

The hero stays hidden until every script runs.

Seven scripts block rendering

They load before the page can paint.

568 requests, 8.7 MB on the homepage

Mostly tags, pixels and app scripts.

Oversized images

Images load far larger than they display.

On the optimised product page, the theme is now a small share of script time. Most of what remains is Google tags, Shopify pixels, mFilterIt, embedded app code and GoKwik, which is why Track B matters.

What we will change

Track A: Theme optimisation

All 6 templates. No change to tracking: every tag and app keeps loading as it does today.

Page type
Changes
All pages
Inline the styles the first screen needs and load the rest without blocking paint. Carry over the trial fixes (layout stability, font loading, non-blocking stylesheets) and check them on every template.
Homepage
Hero banner loads first, at the right size per screen. Space reserved for banners and sliders. Sections below the first screen load later.
Collection pages
First row of product images loads early, the rest on scroll. Space reserved for cards, badges and offer banners. Filter, sort and quick-add code loads only when used.
Content pages
All-page fixes applied to the default page template (13 pages).
Product pages
Trial product page work rolled out to all 3 product templates (107 products). Main product image downloaded once, at the right size. Zoom, lightbox and video player load only when used. Gallery height reserved so the page stays stable.
Track B: Smarter loading of third-party scripts

Needs Durex approval. Third-party scripts now take most of the load time, so this step moves the score the most. Every script still loads and runs on every visit; only the timing changes.

Load immediately, as today
Google Tag Manager, Google Analytics, Meta Pixel and Shopify pixels. Attribution and conversion tracking are unaffected.
Load after first tap or scroll
mFilterIt, Hotjar, Clarity, Snapchat, Bing, Cooee, GoKwik side cart and login, Bik and Smile.
Also in Track B
Lower download priority for large app scripts, such as Cooee's SDK, so product images load first. Before go-live, every tag, GoKwik checkout and login, reviews and chat are checked on the preview theme.
Recommendations for the team that owns Google Tag Manager

We will not change these. Check or remove the placeholder tag "G-FAKEID", consolidate Google tags, which load several separate times, raise mFilterIt's heavy page-load task with the vendor, and remove the Google Translate script if unused.

What stays protected

Everything live stays live

No feature, tag, app or page is switched off. We only change when scripts load.

No data exposure

We do not change how customer, first-party or personal (PII) data is collected, stored or sent. Consent (OneTrust) and checkout logic stay as they are.

No rewrite

We optimise the existing theme code. The site is not rebuilt.

No removals without approval

Unused apps or scripts are removed only with Durex's written sign-off.
