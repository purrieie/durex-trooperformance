What is causing it
01

One hidden element causes most of the layout shift

An invisible screen-reader block in the theme accounts for 0.98 of the homepage's 0.99 CLS.

02

A one-character CSS bug hides the hero

A missing space in the slideshow CSS keeps the hero hidden until every script has run.

03

Seven scripts block rendering

Splide, a duplicate Opinew copy, Offer18 and three Trackier tags load before the page can paint.

04

568 requests, 8.7 MB on the homepage

About three quarters are tags, pixels and platform scripts. Google tags load twice.

05

Images far larger than they display

A 3 MB GIF shown at 280px, 2.5 to 3.6 MB of Cooee GIFs, and logos and product images several times their display size.

04. Scope of work

Theme fixes we ship, vendor fixes we coordinate.

Track 1 is theme code we control. Track 2 sits with third-party apps and needs introductions from the Durex team.
Track 1: Theme-side

Ship the theme fixes

No visual change.
  • Remove the hidden block causing most of the layout shift
  • Defer the seven render-blocking scripts
  • Fix the slideshow CSS so the hero shows without waiting on scripts
  • Resize theme images and swap the 3 MB GIF for a 0.41 MB video
  • Reserve space for the homepage category circles
  • Trim 113 to 193 KB of HTML whitespace per page
Track 2: Third-party apps

Work with vendors to reach 45+

Needs introductions from the Durex team.
  • Interaction-gating: non-critical apps such as the gift-box builder and Cooee load only when a shopper engages
  • Cooee: re-upload campaign images and GIFs at display size
  • GTM clean-up: remove the placeholder and duplicate Google tags. Same data collected
  • Tool overlap: keep one of Hotjar or Clarity, and confirm which affiliate tags are still live
What stays untouched
Revenue, consent and attribution scripts keep loading and firing. At most, their load timing moves.
